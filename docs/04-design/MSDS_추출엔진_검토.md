# MSDS 추출 엔진 — 대안 검토와 채택 결정

> 작성 2026-08-03 · 대상 화면 `msds.html` / `js/msds.js` / `supabase/functions/msds-extract`
> **결정: A안(데모 재생) 채택.** 시연 단계는 비용 0원으로 운영하고, 실문서 분석이 필요한 시점에
> `ANTHROPIC_API_KEY` 시크릿만 등록하면 코드 수정 없이 B안으로 자동 전환된다.

---

## 1. 한 줄 결론

**무료로 MSDS를 실제 인식하는 방법은 없다.** 조사한 모든 무료 경로가 시연에 쓸 수준에 못 미쳤다.
따라서 현재는 사전 검증된 MSDS 3종의 추출 결과를 재생하고(A안), 그 사실을 화면에 명시한다.

## 2. 세 가지 안

| 안 | 비용 | 업로드 문서를 읽는가 | 화면 배지 | 상태 |
|---|---|---|---|---|
| **A. 데모 재생** | **0원** | **아니오** — 사전 추출 결과 재생 | `데모 재생` | **채택 · 현재 운영 중** |
| **B. 시연 기간만 AI 분석** | 수천 원 (시연 10건 기준) | 예 | `AI 분석` | 키 등록만으로 전환 가능 |
| **C. 상시 AI 분석** | 건당 수백 원 | 예 | `AI 분석` | 상용화 시점 |

세 안 모두 **동일한 코드**로 동작한다. 분기는 `js/config.js` 의 `msds.mode` 와 서버의 키 유무로만 결정된다.

### A → B 전환 절차 (코드 수정 없음)

1. https://platform.claude.com → API Keys → 키 발급 (`sk-ant-...`)
2. Supabase 대시보드 → 프로젝트 `qgwmqbtkuvozszgaunlp` → Edge Functions → Secrets → `ANTHROPIC_API_KEY` 등록
3. `msds-extract` 함수 배포 (`supabase/functions/msds-extract/index.ts`)
4. 웹 새로고침 → 로그인 → 배지가 `AI 분석` 으로 바뀜

전환 원리: 클라이언트가 `{probe:true}` 로 서버 능력을 조회한다(Anthropic API 미호출 = 과금 0).
키가 있으면 `ai`, 없으면 `demo` 로 자동 판정하며 결과는 sessionStorage 에 10분 캐시된다.

### B → A 복귀

Secrets 에서 `ANTHROPIC_API_KEY` 를 삭제하면 즉시 데모로 돌아간다(최대 10분 캐시 지연). 과금도 중단된다.

### 강제 고정이 필요할 때

`js/config.js` 의 `msds.mode` 를 `'demo'` 로 두면 키가 있어도 항상 데모로 동작한다(시연 중 실수 방지).
`'ai'` 로 두면 항상 AI 분석을 시도한다.

## 3. 무료 대안 조사 결과 (실측)

실제 MSDS 3종 원본(`03. 과제최종(최종발표)/01. 이의상 과장/`)에 프로토타입을 돌려 측정했다.
추정치가 아니라 실행 결과다.

| 후보 | 비용 | 판정 | 근거 |
|---|---|---|---|
| **브라우저 규칙 파서** (pdf.js + 정규식) | 0원 | **기각** | 39칸 중 12칸 적중 = **약 30%**. UN3077 문서는 12개 필드 중 1개만 추출 |
| **Cloudflare Workers AI** | 무료 10,000 Neurons/일 | 기각 | 통합 방식·정확도 근거 미확보. 학습 미사용 정책은 확인됨 |
| **Groq** | 무료 (카드 불필요) | 기각 | 정량 근거가 3~4배 어긋남. 정확도 근거 0 |
| **Azure AI Document Intelligence** | F0 무료 500p/월 | 기각 | **문서당 첫 2페이지만 처리**, 초과분은 조용히 버려짐. MSDS의 Section 14 는 6~10페이지에 위치 |
| **Tesseract.js** | 완전 무료·무한 | 기각 | OCR 노이즈(0/O, 1/l)가 정규식 매칭을 파괴 |
| **Google Cloud Vision** | 1,000 unit/월 | 기각 | 텍스트만 반환 — 구조화는 별도 필요 |

### 규칙 파서가 실패한 구체적 이유

무료 경로 중 가장 유망했던 후보다. 텍스트 레이어는 3종 모두 온전했고(24,540 / 21,593 / 12,198자)
OCR 자체는 불필요했다. 그런데도 실패한 원인은 **문서 형식의 비일관성**이다.

- **섹션 헤더 형식이 제각각** — `SEC. 14 TRANSPORT INFORMATION` / `14. Transport Information USA, EU` /
  `Information for Transportation`. 정규식이 하위 소제목(`14.7 Bulk transport`)에 잘못 걸리면
  UN·PSN·등급·포장등급이 전부 탐색창 밖으로 밀려난다.
- **값이 라벨보다 먼저 나옴** — 2단 레이아웃 문서는 추출 순서가 `9 Different dangerous material` → `Class:` 라
  `Class:\s*(\d)` 계열이 전멸한다. 좌표 재구성으로만 복구 가능.
- **라벨 표기가 비표준** — `D. Packing grade: 2`(로마자 아님), `C. Transport hazard class: 5.1(8)`(부차위험 괄호),
  `ID Number: UN3480`(공백 없음), `Marine pollutants: Not available`(false 와 미기재 구분 불가).
- **CAS 에 공백이 끼어듦** — 아래첨자 때문에 `7722- 84- 1` 로 추출되어 표준 정규식이 불발.
- **특별규정(SP)은 문서에 아예 없음** — 3종 모두 `Special provision` 0회. UN번호 → 규정표 룩업이 필요하며
  파서로는 원리적으로 추출 불가.

### 부수 성과 — CAS 체크디짓 검증

규칙 파서 자체는 기각했지만, **CAS 체크디짓 검증은 유효성이 실증됐다.**
리튬코발트 MSDS 원문의 `1370-96-6`, `12190-79-7` 이 둘 다 체크디짓 불일치로 걸렸고,
정답은 `1307-96-6`, `12190-79-3` 이었다(다른 문서에 올바르게 기재되어 교차 확인).
**문서 자체의 오타를 잡아낸 사례**이며, 향후 AI 분석 결과의 사후 검증 규칙으로 도입할 가치가 있다.

### 보안 경고 — pdf.js 버전

향후 클라이언트 파싱을 재검토한다면 **`pdfjs-dist` 3.x 계열을 쓰면 안 된다.**
`CVE-2024-4367` — 조작된 PDF를 여는 것만으로 호스팅 도메인 컨텍스트에서 임의 JS 실행이 가능하다.
수정은 4.2.67 에서 이뤄졌고 3.x 백포트는 없다. 이 앱은 제3자 PDF를 여는 것이 기능 본질이고
세션 토큰이 localStorage 에 평문 보관되므로 토큰 탈취로 직결된다.

## 4. 현재 구현 (A안)

### 엔진 판정 순서 — `js/msds.js` `engineFor()`

```
config.mode === 'demo'        → demo (설정 고정)
서버에 API 키 없음             → demo
미로그인                       → demo
파일 미업로드 / 형식·크기 초과  → demo
그 외                          → ai
```

판정 결과와 **그 이유**를 화면 배지에 함께 표시한다. 사용자가 왜 데모로 도는지 알 수 있다.

### 이번에 제거한 것 — 오인식의 원인

기존에는 업로드 파일명의 숫자로 샘플을 추측했다.

```js
// 제거됨 — 파일명 숫자가 UN번호와 우연히 겹치는 샘플을 재생, 못 맞히면 무조건 2번 샘플
var guess = D.MSDS.filter(...)[0] || D.MSDS[1];
```

실제 MSDS를 올려도 무관한 프로파일(대개 UN3480 리튬배터리)이 떠서 **"인식이 안 된다"로 보였다.**

### 대신 넣은 것 — 무작위 자동 선택

데모 모드에서 파일을 올리면 MSDS 3종 중 **하나를 무작위로 선택**해 `LLM-OCR 분석 실행`을 곧바로 활성화한다.
직전에 재생한 샘플은 가능하면 제외해 연속 업로드 시 같은 프로파일이 반복되지 않게 한다.

파일명 추측 방식과 결정적으로 다른 점은 **무작위라는 사실을 화면에 그대로 쓴다**는 것이다.

```
업로드 — sample.pdf (412 KB) · 데모 재생 모드라 이 문서는 분석되지 않습니다. …
재생할 샘플로 리튬이온 배터리 셀(UN 3480)이 무작위로 선택되었습니다 — 아래에서 다른 샘플로 바꿀 수 있습니다.
```

예전 방식은 파일 내용과 관계있는 척했기 때문에 오인식으로 읽혔다. 지금은 시연 흐름이 끊기지 않으면서도
업로드 문서가 분석되지 않았다는 사실이 명시된다. AI 분석 모드에서는 이 자동 선택이 동작하지 않는다 —
결과는 실제 문서에서 나와야 하므로 샘플을 미리 고르지 않는다.

### 실분석 실패 시

무관한 데모 샘플로 조용히 대체하지 않는다. 실패 원인을 그대로 표시하고 재시도 또는 샘플 선택을 유도한다.

## 5. 비용 (B·C안 참고)

`claude-opus-5` 기준 입력 $5 / 출력 $25 per MTok. MSDS 1건은 문서 크기에 따라 **대략 수백 원**.

과금 방어 장치는 이미 구현되어 있다.

| 장치 | 내용 |
|---|---|
| 로그인 필수 | 승인 계정 토큰 없으면 401 — 익명 호출로 인한 과금 불가 |
| status 재확인 | 승인 취소된 계정의 잔여 토큰도 차단 |
| 8MB 제한 | 대용량 문서의 토큰 폭증 차단 |
| 키 미등록 시 | 503 반환 → 데모로 자동 폴백, 과금 0 |

추가로 Anthropic 콘솔에서 **월 사용 한도(spend limit)** 설정을 권장한다.

## 6. 재검토 트리거

아래 중 하나라도 해당하면 이 문서를 다시 열 것.

- 취급 MSDS가 **특정 발행처 양식으로 표준화**될 때 → 규칙 파서의 실패 원인(형식 비일관성)이 사라져 무료 경로가 유효해진다
- 무료 티어에 **문서 전체 페이지를 처리하는 서비스**가 등장할 때 (현재 Azure F0 는 2페이지 제한)
- 월 처리량이 커져 **건당 단가가 문제가 될 때** → 사전 필터(규칙 파서로 명백한 건 선처리 후 AI 호출 축소) 검토
- 화주 문서의 **기밀성 요구가 강해질 때** → 외부 API 전송 자체를 피해야 하므로 로컬 경로 재평가
