`git filter-repo` 로 이력을 재작성하고 force push 했으나 **참조가 끊긴 옛 커밋 객체가
직접 SHA 로 계속 조회**됐다(커밋 3개 · 파일 4종 · 24곳). 저장소 삭제 권한이 없고
free 요금제라 private 전환 시 Pages 가 중단되므로, **값 자체를 무효화**하는 방향으로 처리했다.

### 변경
- **전 계정 비밀번호 교체** — Connect DG 3계정(관리자 1 · 사용자 2) 및 AI_SCM 관리자 1계정
- **`sql/set_passwords.sql`** — 재사용 금지 목록(노출값 · 그 파생값 · `login_id` 로 공개된 사번),
  적용 검증 쿼리, 세션 정리 쿼리를 주석으로 추가
- **RUNBOOK '자격증명 관리' 절 신규** — 원칙 · 사고 경위 · 순환 절차 5단계 · 커밋 전 점검

### 검증
- 노출된 값으로 4계정 전부 로그인 거부 확인 (`dg_login` · `app_login` 실측)
- 직전 값(관리자 임시값 · 사번 · `CHANGE_ME`)도 전부 거부
- 현재 이력에 평문 잔존 0건 (blob · 커밋 메시지 양쪽)

### 남은 위험
- 옛 커밋 SHA 는 GitHub 이 회수할 때까지 조회 가능하며, 이미 복제된 사본은 회수되지 않는다.
  **노출된 값은 이 프로젝트 밖에서도 재사용하지 않는다.**
- 현재 값이 노출값의 접미 파생인 경우 추측 위험이 남는다 — 무관한 값으로의 재교체 권장.

## 2026-08-04 — 데모 재생 모드 샘플 무작위 자동 선택

파일을 올려도 샘플을 고르지 않으면 `LLM-OCR 분석 실행`이 비활성으로 남아 시연 흐름이 끊겼다.
데모 모드에서 업로드하면 MSDS 3종 중 하나를 무작위로 선택해 분석 실행을 바로 연다.
파일명 숫자로 샘플을 찍던 예전 방식과 다른 점은 **무작위라는 사실을 화면에 그대로 쓴다**는 것이다 —
예전 방식은 파일 내용과 관계있는 척해 오인식으로 읽혔다.

### 변경
- **무작위 자동 선택** — `pickRandomSample()` 신규. 직전 재생 샘플은 가능하면 제외해 연속 업로드 시 같은 프로파일이 반복되지 않음
- **AI 분석 모드는 제외** — 결과가 실제 문서에서 나와야 하므로 샘플을 미리 고르지 않음(기존 early return 유지)
- **안내 문구** — 드롭존·안내문·업로드 상태에 무작위 선택 사실과 변경 방법(칩)을 명시

### 수정
- **실문서 분석 죽은 버튼** — `analyze()` 가 `!selected` 로 즉시 return 해 AI 분석 경로에 도달할 수 없었다.
  AI 분기는 `selected = null` 로 둔 채 버튼만 여는데 `selected` 를 채우는 유일한 지점이 분석 성공 시점이라 순환 도달 불가였다.
  실행 엔진 기준(`!selected && !liveReady()`)으로 교체 — `ANTHROPIC_API_KEY` 등록 시 "코드 수정 없이 전환"이 실제로 성립하게 됨
- **진행 문구 잔존** — `pick()` 이 추출표만 되돌리고 `progressText` 는 두어, 새 업로드 후에도 직전 "완료 — 추출 항목 N건"이 남았다
- **케이스 복원 파일명** — `uploadedName` 대입이 `pick()` 보다 뒤라 사용자 파일명 대신 샘플 기본 파일명이 표시되던 순서 오류
- **다국어 회귀** — 드롭존 문구 변경으로 죽은 사전 항목이 된 키를 교체하고, 엔진 배지·판정 이유·안내문 등
  누락돼 있던 문장을 EN/ZH 사전에 등록(문장 중간 `<b>` 를 걷어내 텍스트 노드를 문장 단위로 정리)

### 운영
- **배포 캐시 키 자동화** — `?v=` 수동 갱신이 도입 이후 3회 연속 누락됐다. 배포 워크플로가 `_site` 사본의
  `?v=` 를 커밋 SHA로 치환(원본 파일은 그대로) — 재방문자가 구버전 JS를 받는 문제가 구조적으로 사라짐
- **`manifest.webmanifest` 배포 누락 수정** — 12개 페이지가 참조하는데 워크플로가 복사하지 않아 배포본에서 404였음

### 검증
- jsdom 회귀 25/25 통과 — 자동 선택·버튼 활성·분포(3종 전부 등장)·직전 샘플 연속 중복 0회,
  `Math.random` 고정 시 제외 로직 결정적 확인, 비허용 형식·단일 샘플 방어 포함
- 계정 3건 로그인 실측(관리자 1 · 사용자 2), 직전 비밀번호 거부 확인

### 보안·정합성 강화 (6관점 적대 검증 확정 9건 반영)
- **OTP 무차별 대입 차단** — `dg_email_codes.attempts` 추가, 오입력 5회 초과 시 코드 즉시 소각(가입·재설정 공통). 발송 측은 새 코드 발급 시 같은 주소·목적의 기존 미사용 코드를 무효화해 동시 유효 코드를 1개로 유지

- **메일 발송 남용 방어** — 레이트리밋 조회 실패 시 통과하던 fail-open을 차단(fail-closed)으로, 주소당 60초 제한을 목적 무관으로 통합, 전역 시간당 30건 상한 추가, 인증코드를 `crypto.getRandomValues` 기반으로 교체
- **케이스 동기화 유실 수정** — 확정 직후 화면 이동으로 1.5초 디바운스가 버려지던 문제를 `pagehide` 즉시 flush(keepalive) + 다음 페이지 catch-up으로 해소. catch-up은 마지막 업로드 서명과 다를 때만 전송해 오래된 브라우저가 타 기기 최신본을 덮어쓰지 않음. 세대 카운터로 늦게 도착한 구버전 응답 무시
- **MSDS 실분석 견고화** — `validToken`이 status까지 확인 · `stop_reason=max_tokens`(출력 잘림)를 파싱 실패로 넘기지 않고 원인 안내 · `effort: medium`으로 thinking 토큰 여유 확보
- **오프라인 오탐 수정** — `validate()`가 네트워크 오류를 세션 만료와 구분(일시 장애 시 로그인 세션 유지)
